## 1. 目标与范围

### 1.1 产品目标
个人一页看板：把「要处理的邮件」「当下育儿 Tips」「GitHub 活跃度」收拢到同一首页，模块可开关、可插拔，首屏信息密度可控。

### 1.2 第一版（V1）模块
| 模块 ID | 名称 | 数据源 | 用户配置 |
|---------|------|--------|----------|
| `mail-todos` | 邮件待办 | Gmail（用户已有连接） | 连接 Gmail |
| `parenting-tips` | 育儿 Tips | 本地规则 / 静态+轻量内容源 | 小孩年龄、状况标签 |
| `github-activity` | GitHub 活跃度 | GitHub API（用户已有连接） | 连接 GitHub；用户 `Avocado-0324` |

**暂缓**：资产 / 网银相关模块。任何实现不得要求或存储银行账号、密码、OTP、会话 Cookie。

### 1.3 非目标（V1）
- 不写邮件、不自动回复、不发 Slack
- 不登录网银、不拉取账户余额
- 不做多用户 / 多租户
- 仓库尚未创建；等用户在 GitHub 建空仓并告知后再开 PR 流水线

## 2. 技术骨架

- **框架**：Next.js（App Router）
- **模块目录**：`modules/<module-id>/`
- **壳层**：`app/`（布局、首页编排、首次配置）、`lib/`（共享 auth、缓存、错误类型）
- **原则**：壳层只编排；业务与数据访问落在模块内；模块之间禁止直接 import（经壳层契约或共享 `lib` 类型）

建议目录：

```
app/
  layout.tsx
  page.tsx                 # 首页：读开关 → 渲染已启用模块
  onboarding/              # 首次配置流
modules/
  mail-todos/
    manifest.ts
    server.ts              # 数据拉取（服务端）
    ui.tsx                 # 卡片 UI
  parenting-tips/
    manifest.ts
    server.ts
    ui.tsx
  github-activity/
    manifest.ts
    server.ts
    ui.tsx
lib/
  module-registry.ts       # 注册表：扫 manifest
  module-types.ts          # ModuleManifest / ModuleProps 等
  connectors/              # Gmail / GitHub 薄封装（经用户已有 MCP/连接）
```

## 3. 模块接口（Manifest）

每个模块导出一份静态 `manifest`，壳层用它做注册、开关、权限与布局。

### 3.1 必填字段

```ts
export type ModuleId = 'mail-todos' | 'parenting-tips' | 'github-activity';

export type ModuleManifest = {
  /** 稳定 ID，与目录名一致 */
  id: ModuleId;
  /** 展示名（中文） */
  name: string;
  /** 一句话说明 */
  description: string;
  /** semver，模块自身版本 */
  version: string;
  /** 首页默认是否开启（首次配置前） */
  defaultEnabled: boolean;
  /** 所需外部连接；空数组 = 无外部依赖 */
  requires: Array<'gmail' | 'github'>;
  /** 所需用户本地配置键 */
  configKeys: string[];
  /** 卡片建议尺寸（体验可覆盖） */
  layout: {
    minWidth: 'half' | 'full';
    priority: number; // 越小越靠前
  };
  /** 无数据 / 未配置 / 权限失败时的空态文案 key */
  emptyStates: {
    unconfigured: string;
    noData: string;
    authFailed: string;
  };
};
```

### 3.2 运行时契约

```ts
/** 壳层注入给模块的只读上下文 */
export type ModuleContext = {
  userConfig: Record<string, string | number | boolean>;
  connectors: {
    gmail?: { ready: boolean };
    github?: { ready: boolean; login?: string };
  };
  /** 模块开关；壳层保证仅对 enabled=true 调用 load */
  enabled: boolean;
};

/** 模块服务端加载结果（可序列化） */
export type ModuleLoadResult =
  | { status: 'ok'; data: unknown }
  | { status: 'unconfigured' }
  | { status: 'no_data' }
  | { status: 'auth_failed'; reason?: string }
  | { status: 'error'; message: string };

/** 每个模块必须实现 */
export type ModuleContract = {
  manifest: ModuleManifest;
  /** 仅服务端；禁止在客户端持有 token */
  load(ctx: ModuleContext): Promise<ModuleLoadResult>;
  /** 客户端卡片；只吃 load 的可序列化结果 */
  Card: React.ComponentType<{ result: ModuleLoadResult }>;
};
```

### 3.3 开关与配置存储（V1）
- **开关**：`user_settings.modules[id].enabled: boolean`
- **本地配置**：如 `parenting.childAgeMonths`、`parenting.tags[]`
- **连接状态**：以连接器就绪为准（Gmail / GitHub），不在本应用库中存 refresh token 明文以外的密钥材料；若平台已托管连接，本应用只存「已连接 / 未连接」与必要的非敏感元数据（如 GitHub login 展示名）

## 4. 数据流

```
用户打开首页
    ↓
壳层读取 user_settings（开关 + 本地配置）
    ↓
壳层查询连接器就绪状态（gmail / github）
    ↓
对每个 enabled 模块并行调用 module.load(ctx)
    ↓
模块内部：经 lib/connectors 调 Gmail/GitHub API，或读本地内容源
    ↓
返回 ModuleLoadResult → 壳层传给 Card
    ↓
Card 按 status 渲染：内容 / 空态 / 权限失败 / 通用错误
```

### 4.1 分模块数据要点

| 模块 | 入 | 出（建议） |
|------|----|------------|
| `mail-todos` | Gmail 只读检索（待办/未读约定由体验定） | 标题、发件人、时间、deep link；上限 N 条 |
| `parenting-tips` | 年龄月数 + 状况标签 | Tips 列表（标题、摘要、可选链接）；可全静态 |
| `github-activity` | GitHub API（events / contributions 摘要） | 近 7/30 天提交/PR/issue 计数 + 最近活动条 |

### 4.2 缓存与刷新（V1 建议）
- 服务端短缓存：邮件 / GitHub 60–120s；育儿 Tips 可按配置变更失效
- 首页提供「刷新」触发 revalidate；不做后台轮询

## 5. 安全边界

| 允许 | 禁止 |
|------|------|
| 使用用户**已授权**的 Gmail / GitHub 连接做只读拉取 | 索要、存储银行密码、网银 OTP、卡号、CVV |
| 本地存储小孩年龄与状况标签（非敏感偏好） | 在客户端暴露 access token |
| 模块级 `auth_failed` 降级空态 | 跨模块共享原始 API 响应而不经契约 |
| 日志打模块 id / status / 耗时 | 日志打印邮件正文全文、token、Authorization 头 |

**资产模块**：明确 out of scope；实现与验收若发现任何网银相关依赖 → 阻塞并回退架构评审。

**密钥**：连接凭证只走平台已有连接通道；本仓库 `.env` 仅放非用户密钥的应用级配置（若有）。禁止把用户 token 写入 git。

## 6. 里程碑 M0–M3

| 里程碑 | 目标 | 完成定义 | 主要负责 |
|--------|------|----------|----------|
| **M0** 契约冻结 | Manifest / ModuleLoadResult / 目录约定定稿；体验出首页线框与首次配置流；空仓就绪 | 架构说明书 ≥ v0.2；体验线框可交付实现；用户告知仓库 URL | 架构 + 体验；用户建仓 |
| **M1** 壳层可跑 | Next.js 骨架、`module-registry`、开关持久化、onboarding 骨架、三模块占位 Card | 本地可启动；开关能隐藏/显示占位模块；未连接时走 `unconfigured` | 实现（架构答疑） |

| **M3** 打磨与合并 | 信息密度、加载态、回归清单全绿；主分支可演示 | PR 合并；验收给「通过」意见 | 体验微调 + 实现 + 验收 |

## 7. 分工边界

| 角色 | 负责 | 不负责 |
|------|------|--------|
| **架构（本助手）** | 模块契约、目录与数据流、安全边界、里程碑、跨角色冲突裁决 | 不写业务 UI 细稿；不直接开功能 PR（除非契约示例） |
| **体验** | 信息架构、首页布局、模块开关与首次配置文案/线框、卡片信息密度；与架构对齐模块边界 | 不定 API 字段形态；不改 manifest 必填集（需提变更申请） |
| **实现** | 按契约与线框写代码、接 Gmail/GitHub、开 PR、自测；模块可插拔 | 不登录网银；不扩 V1 模块；不擅自改契约 |
| **验收** | 模块开关、边界、空态、权限失败、回归清单；PR 上给通过/阻塞 | 不扩 scope；不代替实现改代码 |
| **PM（Grok Bot）** | 排期、对齐、催建仓与连接 | 不替代架构定契约 |

### 7.1 变更流程
1. 体验或实现若需改 manifest 字段 → 提变更点给架构  
2. 架构更新说明书小版本（v0.x）并通知三方  
3. 实现跟 PR；验收按新契约回归
