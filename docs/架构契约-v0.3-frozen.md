## 0. 关键决策

| 项 | 决定 |
|----|------|
| 存储 | **Neon Postgres**（Vercel Marketplace 免费档），`DATABASE_URL` 仅服务端 env |

| 写权限 | 会话（手动、CSV） + 专用写入密钥（截图结果，仅能写资产数据，不能读） |

## 2. 数据表

```sql
accounts(
  id uuid pk,
  name text not null,                 -- 例："SBI 特定"
  type text not null check (type in ('tokutei','nisa_growth','nisa_tsumitate','cash','other')),
  broker text,                        -- 'sbi' 等，仅标签
  created_at timestamptz default now()
)

instruments(
  id uuid pk,
  symbol text not null,               -- 例：'7203' / 'VOO' / 投信协会コード
  name text not null,
  asset_class text not null check (asset_class in ('jp_stock','us_stock','fund','etf','bond','reit','crypto','other')),
  currency char(3) not null,          -- 'JPY' / 'USD'
  unique(symbol, currency)
)

snapshots(
  id uuid pk,
  as_of date not null,                -- 持仓日期
  source text not null check (source in ('manual','csv','screenshot')),
  batch_id uuid null references import_batches(id),
  note text,
  created_at timestamptz default now()
)
-- 同一 as_of 可有多条（不同账户分次录入）；估值时取每个账户在 as_of 当天或之前的最新一条

positions(
  id uuid pk,
  snapshot_id uuid not null references snapshots(id) on delete cascade,
  account_id uuid not null references accounts(id),
  instrument_id uuid not null references instruments(id),
  quantity numeric(24,8) not null,
  avg_cost numeric(24,8) not null,    -- 原币
  price numeric(24,8) not null,       -- 原币，快照时点
  fx_rate_to_jpy numeric(14,6) not null default 1,
  unique(snapshot_id, account_id, instrument_id)
)

cash_balances(
  id uuid pk,
  snapshot_id uuid not null references snapshots(id) on delete cascade,
  account_id uuid not null references accounts(id),
  currency char(3) not null,
  amount numeric(20,2) not null,
  fx_rate_to_jpy numeric(14,6) not null default 1
)

cash_flows(                           -- 外部入金/出金（不含账户间划转）
  id uuid pk,
  account_id uuid null references accounts(id),
  date date not null,
  direction text not null check (direction in ('deposit','withdrawal')),
  amount_jpy numeric(20,2) not null check (amount_jpy > 0),
  note text,
  source text not null check (source in ('manual','csv','screenshot')),
  batch_id uuid null references import_batches(id)
)

import_batches(
  id uuid pk,
  source text not null check (source in ('csv','screenshot')),
  idempotency_key text unique not null,
  filename text,
  row_count int,
  status text not null check (status in ('committed','reverted')),
  created_at timestamptz default now()
)
```

撤销：按 `batch_id` 删除该批次写入的 snapshots / cash_flows，`import_batches.status='reverted'`（仅会话可操作）。

## 3. 计算口径

- **持仓市值(JPY)** = Σ quantity × price × fx_rate_to_jpy  
- **现金(JPY)** = Σ amount × fx_rate_to_jpy  
- **总资产** = 每个账户最新快照的持仓市值 + 现金  
- **净投入** = Σ deposit − Σ withdrawal  
- **累计盈亏** = 总资产 − 净投入；**累计收益率** = 累计盈亏 / 净投入（净投入 ≤ 0 时不显示）  
- **未实现盈亏**（按持仓）= quantity × (price − avg_cost) × fx_rate_to_jpy  
- **真实年化 XIRR**：现金流取投资者视角，入金为负、出金为正，最新估值日的总资产作为终值（正）；按实际天数/365；Newton 迭代，不收敛时改用二分法，区间 [−99%, +1000%]。  
  出现以下情况时返回 `null`，卡片显示「数据不足」：没有任何入金、首笔入金距今不足 30 天，或计算不收敛。  
- **分布**：按账户类型、按 asset_class，各自占总资产的比例（现金单列一项）。

验收用例须含：单笔入金持有 1 年、分批入金、中途出金、外币持仓、净投入为 0 或负。

## 4. 卡片数据契约

```ts
export type PortfolioData = {
  asOf: string;                       // 最新快照日期（ISO date）
  baseCurrency: 'JPY';
  totalJpy: string;                   // 金额统一用十进制字符串，避免精度丢失
  netContributionJpy: string;
  pnlJpy: string;
  pnlRatio: string | null;
  xirr: string | null;                // 例："0.0734"；null 时显示「数据不足」
  allocationByAccount: Array<{ accountType: string; label: string; valueJpy: string; ratio: string }>;
  allocationByAssetClass: Array<{ assetClass: string; label: string; valueJpy: string; ratio: string }>;
  topHoldings: Array<{ symbol: string; name: string; valueJpy: string; unrealizedPnlJpy: string }>; // ≤5
  stale: boolean;                     // 最新快照超过 7 天为 true，卡片提示「数据已 N 天未更新」
};
```

刷新：只有写入后才会变化。写入成功后调用 `revalidateTag('portfolio')`，不设轮询。

## 5. 接口

| 路由 | 鉴权 | 作用 |
|------|------|------|
| `GET /api/portfolio/summary` | 会话 | 卡片数据（也可直接在 Server Component 里 load） |
| `POST /api/portfolio/positions` 等 CRUD | 会话 | 手动录入/编辑账户、持仓、现金、入出金 |
| `POST /api/portfolio/import/csv?dryRun=1` | 会话 | 解析 SBI CSV，返回预览和逐行错误，**不写库** |
| `POST /api/portfolio/import/csv` | 会话 | 提交；整批放在一个事务里，任意一行失败就整批回滚 |
| `POST /api/portfolio/ingest` | **写入密钥** | 写入截图识别结果（见下） |
| `POST /api/portfolio/batches/:id/revert` | 会话 | 撤销一个批次 |

### 5.1 CSV
- SBI 证券导出的 CSV 是 **Shift_JIS** 编码，需要用 `TextDecoder('shift_jis')`（或 iconv-lite）解码；表头先按 SBI 现行格式做映射，映射表放在 `modules/portfolio/import/sbi.ts`。  
- 错误格式：`{ row: number; column?: string; message: string }[]`，row 是 CSV 的物理行号（含表头，从 1 开始）。  
- 文件 ≤ 1MB；数字去掉千分位逗号后再解析；遇到无法识别的表头，直接整体报错，并列出缺失的列。

### 5.2 截图写入 `POST /api/portfolio/ingest`
- Header：`Authorization: Bearer <PORTFOLIO_INGEST_KEY>`（≥32 字节随机串，Vercel env + Grok Bot 私密存储；用 `timingSafeEqual` 比较）。  
- Body：`{ idempotencyKey, asOf, source: 'screenshot', accounts?, positions?, cashBalances?, cashFlows? }`，用 zod 严格校验，未知字段直接拒绝。  
- 只能写入，不能读取：响应只返回 `{ batchId, inserted: { positions, cashFlows, ... } }`，不回显任何资产数据。  
- 同一个 `idempotencyKey` 重复提交时返回第一次的结果，不会重复写入。  
- 写入前必须已由用户在 1:1 聊天里确认（这条流程约束由 Grok Bot 负责）；写入后卡片上标注来源「截图」，可撤销。  
- `middleware.ts` 的 matcher 要放行 `/api/portfolio/ingest`，这个路由只认密钥，不认会话。

## 6. 安全

- 禁止：网银/券商登录、存券商账号密码/OTP、把资产数值写进日志、在客户端持久化资产数据（localStorage 等）、在模块之间互相 import server 代码。  
- 所有资产相关路由都要加上 `export const dynamic = 'force-dynamic'`，并设置 `no-store`。  
- 写入密钥只授予资产写入权限，可以随时轮换；轮换后旧密钥立即失效。  
- 仓库建议改成 Private（资产数据本身不会进仓库，但迁移文件、导入映射等实现细节都在里面）。  
- 截图识别结果在写库前，只存在于 Grok Bot 的私聊上下文里，看板不保存截图原件。

## 8. 冻结时的决定（原「待确认」）

1. 位置与入口：已按体验稿 v0.4 定，见 §7.5；录入在独立的 `/portfolio` 页面，设置页只管开关。总览区显示总资产、累计盈亏、年化，持仓模块关闭时不显示。
2. 币种：V1 支持 `JPY` 和 `USD`，其他币种推迟到用户确认后。外币持仓按快照存一个手动填写的汇率 `fxRateToJpy`（`numeric(18,6)`），所有汇总都换算成日元。缺汇率的快照不参与汇总，卡片提示「缺少汇率」，不能当作 0 处理。
3. 投资信托：`instruments.kind = 'fund'`。估值公式为 `口数 × 基準価額 ÷ unitBasis`，其中 `unitBasis` 默认 10000（SBI 的投信按每一万口报价），存在 instrument 上，股票和 ETF 为 1。不允许在代码里写死 10000。
4. 数据库：Grok 在用户已登录的 Vercel 上开通 Neon。开通前，持仓模块可以合入但保持默认关闭；没有 `DATABASE_URL` 时 `load` 返回 `error`，文案为「数据库未配置」，页面不能崩。
